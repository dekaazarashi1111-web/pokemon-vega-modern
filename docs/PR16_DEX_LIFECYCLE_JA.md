# PR16 図鑑load・newgameの候補lifecycle

正式ROMと正式Save101を保持する。候補の部分受入を全consumer接続や製品完成へ拡張しない。正式受入の原本run/source/新saveは同名checkpointを正とする。

## 接続

- Mirageのliteral0x09391114からpost-QOL wrapperへ接続する。HOF専用type3はmain MDX/globalを変更せず元QOLを一度呼ぶ。
- main load前にMDXをInvalidateし、前sessionのvalid RAMが内側load失敗を隠すのを防ぐ。元QOLを一度呼び、返値1/255でMDXがvalidなら同じMDXとstatusを保持する。
- 255は片bank破損時の正常fallbackも含む。無条件失効してはいけない。返値1/255でMDXがinvalidならglobal0x030053F0をINVALID=2とし、返値1だけ255へ変える。元status0/2/4とtype3は変更しない。
- stockは内側loaderの返値を捨て、cold callerも最終returnを捨ててglobalを読む。global255はContinueを残すため、return255だけでは遮断できない。global2は既存警告後にNew Gameだけを表示し、SaveBlock2 RAM/設定を初期化する。Flash消去・保存はgateから実行しない。専用の修復/再試行UIは新設していない。
- CFRU literal0x09097178からwipe後tail wrapperへ接続する。元28byte frameとr4-r11を保持し、SPを動的8byte整列してInitNewを一度呼び、0x0805432Dへtailする。通常LR returnによる循環を避ける。

## 通常ゲームの受入境界

同じ候補だけで、既存Save101の作業コピーからlegacy208byteを同じstock bankから取り込み、MDX522byteを通常Saveへ入れ、別processのcold Continueで同じMDXを読む。別レーンでは消去Flashから通常NewGameの固定入力traceを使い、初回Saveと独立cold Continueを検証する。

最初のrun37231227293ではSave101→候補Save102→coldの2processは完走し、MDX/party600byte/Bag/進行hash、全SaveRTC不変を確認した。次のNewGame初回SaveはMDX/保存自体の検査を通過したが、進行flags/varsの全hash差分で停止した。成功したSave101区間は原本artifactから再検証し、再実行しない。NewGame側の差分はSB1+0xFE7 bit6、FLAG_OPENED_START_MENU=0x83Eの1bitだけ。初回STARTのFlagSet→ShowStartMenuを署名窓と固定sourceから同定し、保存原本の1byteを逆変換すると保存前の全進行hashへ一致する。旧0x808/他vars/expanded領域の変更は許容しない。初回NewGame SaveはgDifferentSaveFile=1によりtype4であり、通常Save101のtype0と分ける。blank Flashからの初回type4は既存異種save上書きの全副作用を証明しない。

NewGame初回Save原本run37231607258は実Save1を保存済みなのでintro/Saveを再走せず、独立coldだけを後続runで実行する。2つの診断run全体のfailureは履歴のまま保持する。

通常runnerはst_open/st_keys/st_saveのみを入口にし、最初のframe前から7種類のhost書込みAPIを拒否する。旧fixture main、si_call/si_transaction/si_openは到達させない。旧scratch stack0x0203DB00..0x0203DF80は新MDXと重なるため使用しない。新ownerへの自然登録はまだ検証していない。旧鏡から新owner bitを推測して増やさない。
