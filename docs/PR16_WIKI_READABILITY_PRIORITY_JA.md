## 1. 優先順位と目的

所有者は、まず人が読める資料で現状を把握し、別AIともバランス案を検討してから実編集へ移りたい。現R0の生成・検証・公開は済んでいるが、検索補助の取りこぼしと技術情報の露出により誤判断を招く部分がある。したがって**まず閲覧用Wikiの小修正だけを実装・検証・記録・提示まで完了する**。保存解析・CI全体修復・追加フォーム実装を先行させない。

現在の作業選択は同じ `content/modernization/pr16_wiki_first_execution_plan.json` の `next_action` と `owner_execution_plan.wiki_readability`。本書は旧長期方針の「R0完成なら保存容量へ戻る」条件より優先する。旧R0の `review_ready=true` や8個の完了flagだけで今回を飛ばしてはならない。本書の完了条件を満たした後は既存の長期方針へ戻る。AGENTS.mdの安全・記録・Git規約は継続する。

毎回の通常の続行指示だけで、未完の実装から続ける。方針を再説明するだけ、メモを増やすだけ、取得方法を教えるだけでは閲覧改善の完了ではない。別日付の進捗JSONを増やさず同じ状態を更新する。

## 3. 修正範囲は3点だけ

### A. 誤解を招く検索補助

実例: R0の `pokemon/3.md`（リーテイル）は「回復候補」にすいとる/ねむるしか表示しない一方、全習得表にはLv46こうごうせいがある。まずこの表示と `scripts/pr16_wiki_r0_build.py` の `move_roles` を照合し、同じ原因の出力範囲を限定する。これは習得表へのこうごうせい新規追加ではない。

既存の技情報・effect分類で確実に直せるものは共通処理を修正する。1ページや1speciesだけの手当てでは終えない。ただし全1063技の実効果解析を新規に開始しない。網羅性を証明できない役割要約は主要比較表から外すか、「参考抽出・漏れあり」と明示し、空の抽出を「その技を覚えない」と断定しない。未分類を「未分類/要全習得確認」、確認済みの不存在と区別する。

全習得表へのリンクを近くに置く。直接習得、進化前/フォームからの持越し、条件付き繁殖、入手段階を混ぜない。回復・積み・妨害等を自動的な強さ評価にしない。リーテイルの既知例について、修正版でこうごうせいを取りこぼさないか、網羅しない要約が判断根拠として露出しないことを試験する。単なる警告追加で依然誤誘導する表を残さない。

### B. 主要MD一覧を人向けにする

まず読む表は `VEGA_BALANCE_INDEX.md`、`POKEMON_INDEX.md`、`MOVE_INDEX.md`、`ABILITY_INDEX.md`。ベガ限定/全種族、内部用行/通常種/特殊フォームの区別を保つ。

- ポケモン: 名前、フォーム、タイプ、HP/攻撃/防御/特攻/特防/素早さ/合計、通常特性1/2・夢特性を中心にする。
- 技: 名前、タイプ、分類、威力、命中、PP、優先度、既存の短い説明と詳細リンク。0/特殊値を通常の数値として誤解させない。
- 特性: 名前、既存の説明、所持対象へのリンク、短い確認状態。長いhandler/native辞書を主要列へそのまま表示しない。

stable key、数値ID、source/検証状態は削除せず、短い識別欄・詳細ページ・折り畳み・機械読取層へ分離する。Markdownで既存の基本性能と全習得表を読め、必要に応じ技/特性の詳細へ移れることを優先。全4514ページの文章校正やサイト新設を必須にしない。

詳細MDの大きなJSONは、人向け要約と技術詳細を区分する。曖昧な供給/効果は曖昧なまま明示し、未確認を未実装・使用不能・検証済みへ変換しない。古い説明文字列を完全な実効果仕様と称さない。自動抽出の役割タグと正式な習得データも区別する。

### C. ローカル検討の入口と保存用パッケージ

冒頭に「まず読む一覧」「気になる系統の全習得」「技/特性の詳細」「参考JSON」の読む順序を示す。4,514ファイルを一度に読む指示にしない。R0.1がゲームへ直接投入する形式でなく、同じ固定データからの閲覧資料であると明示する。

修正版の実在する固定commit入口、取得できる閲覧用ZIPまたは再現可能なWiki限定パッケージを用意し、ローカル展開とAIへの読ませ方を説明する。方法だけを未試験で書いて終わらず、生成・内容・展開を確認する。パッケージは改善した一覧と必要な詳細/参照先を含め、相対リンクを壊さない。旧R0詳細をリンクで再利用する場合は、その依存を同じ構成で同梱する。参照不能な外部pathは制限として明記し、主要閲覧導線の欠落は解消する。

ファイル数、各fileまたは一覧manifestのsize/hash、入力commit、閲覧版、ZIPのhashを記録する。資料のみを対象にし、ROM/save/private入力/credential/.git/実行環境を同梱しない。既存artifact/明示的な局所exportを使い、閲覧ZIPのために公開Releaseを作らない。新Webアプリ、検索サーバ、PDF/表計算への全面変換、単一巨大ファイルへの統合は必須にしない。

別AIへの案内は「固定版の一覧→指定系統の全習得/関連詳細、検討のみ、原本とゲームを編集しない」。所有者が案を検討するための資料提供であり、提案書を書かせたり承認を今求めたりする工程ではない。

## 4. 検証と完了条件

影響する表示生成器・閲覧出力・パッケージだけを検証する。既存成功原本を再採取せず、入力hash不変の生成/試験は再利用する。表示修正のためのROM再構成、ARM再compile、ゲームプレイ、保存・戦闘native再実行は不要。元の全体CI/guardの失敗を抹消・無効化せず、今回の限定結果と区別する。

次をすべて実施し、 `wiki_readability.completion_gates` と証拠へ記録したところで完了する。

1. 既知の役割要約の取りこぼし/空抽出誤断定への対応と限定回帰がある。
2. 人向け主要MD一覧と個別全習得への導線を実物で確認した。
3. R0の数値・特性割当・技性能・全習得経路/条件・機構対応の意味が不変。表示派生物（役割タグ等）の変更は別差分にする。
4. R0と旧Wiki/原本/受入証拠が不変。出力のファイル集合・相対リンク・内容の決定性を確認し、checkの書込副作用がない。
5. 閲覧用パッケージを生成・検査し、展開後の入口・参照先・ファイル集合・hash・非公開入力非混入を確認した。
6. 固定の閲覧入口、公開commit、DL方法、件数/size/hash、既知の制限、限定検証結果、両ログと引継ぎを保存し、所有者へ提示した。

ゲーム情報部分の意味不変と表示用semantic hashを分離する。役割タグが直れば表示全体のhashが変わってよい。古いsemantic hashに合わせるために検査や修正を戻さない。

本セッションで承認されたのは上記の限定改善であり、追加の全効果監査や保存修復を完了条件に増やさない。重要入力に真の不足があれば、該当入力修復へ限定して続ける。解決できない外部入力は具体的に記録するが、勝手に本作業を飛ばして保存解析へ戻らない。
