## これまでの直接呼出し試験との違い

初期の親個体・手持ち・開始マップだけを隔離fixtureとして設定する。その後の預入、生成、受取、
孵化、保存、Continueは通常の入力・フレーム進行で観測する。預かり屋の特殊関数を直接呼んだり、
タマゴ生成フラグ・歩数・孵化カウンターを書き換えたりしない。
観測中はmCoreのbus/raw 8/16/32-bit書込とwriteRegisterの計7 APIを禁止する。
区間外の個体検査はCPU状態を復元するnative GetMonDataで行い、結果をfixtureで作り直さない。

実マップの女性との会話・手持ち選択で両親を預け、歩行でタマゴを生成する。実際のドアを通って
屋外の男性から受け取り、通常セーブ後に元coreを破棄する。別coreの通常Continueで復元した
タマゴを通常歩行で孵化させ、ニックネームを拒否し、さらに通常セーブ・別core Continueを行う。
各条件につき3 coreを使用するが、成功ケース数は8、プロセス数も8であり、24件の別ケースとは数えない。

## 8条件と期待値

対象は既採用のピカチュウの親とピチューの子。数値は本プロジェクトの固定IDであり全国図鑑番号ではない。
親からの `175` と `273` の継承、でんきだま `202` による `344`（ボルテッカー）を分ける。

| 母がでんきだま、両親が対象技を保持 | 84, 175, 273, 344 | 30, 15, 10, 15 |
| でんきだまなし、両親が対象技を保持 | 39, 84, 175, 273 | 30, 30, 15, 10 |

| 母だけが対象技を保持 | 39, 84, 273, 0 | 30, 30, 10, 0 |
| 両親とも対象技なし | 39, 84, 0, 0 | 30, 30, 0, 0 |
| 同じ対象技を両親が保持 | 39, 84, 175, 0 | 30, 30, 15, 0 |
| 対象技なし、父がでんきだま | 39, 84, 344, 0 | 30, 30, 15, 0 |

レベル1の初期技、通常タマゴ技の集合、PPはROMの正本テーブルを独立に読む。
ボルテッカーは通常タマゴ技集合に含まれないことも検査し、条件付き技を全親へ配る誤りを拒否する。
各保存の前後で手持ち200 bytes、預かり屋284 bytes、保留タマゴ402 bytesを比較する。
手動セーブ2回に加え、孵化登録によるnative保存1回をフレームごとに観測し、合計3回を要求する。
RTCや保存を無効化せず、既存のmGBA remap対処は観測開始前に実行し、flash 128 KiBの不変を確認する。
