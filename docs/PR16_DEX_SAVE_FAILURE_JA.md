# PR16 図鑑invalid-liveの非破壊的保存失敗

正式ROM/Save101を保持する。全consumer/全save modeの受入ではなく、図鑑RAMがinvalidで保存を拒否した場合の境界を閉じる。

## 修復した2つの誤成功

Stage61はinvalid-liveをFlash書込前に255で拒否する。しかしstock TrySavingDataは返値を捨て、damaged mask0なら成功1へ変えていた。外側QOLはその成功を見てsector31を保存し得る。さらにstock SaveFailedのTryWipeDamagedSectorsもmask0ならTRUEとなり、保存完了表示へ変わっていた。

TrySavingDataの0x080DB360にpost-result gateを接続する。返値255でMDX invalidなら0x080DB36Eへ戻し、gSaveAttemptStatus=255と返値255を保持して、元START Saveの通常エラー文へ返す。既存callerのSP/r4–r11/LRを保持し、Validateを呼ぶ時だけSPを8byte整列する。load status0x030053F0は使わず、save attempt0x03005470を元stock continuationに処理させる。

TryWipe入口0x080F64A8にもValidate gateを置く。invalid MDXはFALSEだけを返し、wipe/program/erase/retryを行わない。validの場合は元8byteのprologueと12byte frameを復元して0x080F64B0へ続行する。新しいmutable latch、架空のdamaged sector、InitNewや暗黙修復は導入しない。

## SaveFailedの別owner衝突を検出した経緯

最初の104byte gate候補0b86667cは、隔離152caseに成功したが、実画面は不受入。通常ContinueしたSave101作業コピーへCRC1byteだけを注入して保存を試すと、frame1922でMDXが変化した。

追加のread-only CPU/DMA store observerを持つrun37235631389では、frame1921、destination0x0203DB40/width2/dma7、SaveFailed state2/active1でMDX先頭2byteの変更を検出した。DMA中のraw CPU PCを要求元PCとは呼ばない。固定ROMのSaveFailed case1→SaveMapTiles、source0x0600C000/destination0x0203B0E8/size0x4000の署名窓と照合して帰属する。

旧SaveMapTilesの16KiB退避0x0203B0E8..0x0203F0E8はMDXだけでなく拡張flags/vars、Collection/QOL/Circus等とも重なる。RestoreMapTilesはそれをVRAMへ戻すだけで、上書きした拡張save ownerを復元しない。さらにvideo-state0x0203F0EC以降のcallback/GPU/text色退避がResearch volatile owner0x0203F0A0..0x0203F100へ重なる。tilesだけの移設では不十分。

このためinvalid-live拒否では専用SaveFailedを起動せず、既存の通常保存エラー文へ返す。valid-liveの実Flash失敗が入る旧専用画面の全owner修復は別の未完工程であり、一般的な失敗処理全体を安全化したとは主張しない。

受入済みbattle候補41d6a334からだけ生成し、監査済み残余272byteの0x095FFEF0へ160byteを追加する。新allocator111owner/overlap0、以前の110owner全byte、codec/scheduler/load/newgame/battle gatewaysと全未宣言ROM byteを保持し、全ROM逆変換を確認する。新候補SHA256はd3dcb55ad09a509fa247e65a3ca3db1de4bdd5b5534288b2b03ddbacca65b314。

初回isolated run37234821383の152caseは、result gate24、wipe gate16、authorityなしmode32、direct writer80。新source82912f7d/run37235903199は変更したresult gate48と不足oracle60の合計108caseを実行。旧152caseを丸ごと再走せず、exact wipe dispatch8、非zero counter101/first7の復元32、正しいdirect引数/異常descriptor・buffer20を追加した。valid wipe成功→実再保存retryは未受入。

実UIはSave101のprivate copyを通常Continueし、barrier7を最初のframe前から保持する。唯一のhost例外はstable fieldで0x0203DB44へ旧CRCbyte XOR1を一度書くこと。CPU/frameを動かさず全EWRAM/IWRAMを比較し、その1byte以外が不変であることを確認する。以後は通常START/SAVE/確認/Aとゲーム内処理のみで、MDX522byte、counter101、全Flashを保持し、process close後に元Save101の全131088byte/RTCまで一致することを要求する。

エラー文字列41byteのoffset14は入力待ち改ページであり、printer0のactive/state2をread-onlyで確認して改ページAを押す。callbackF1F5中にAを全て止めていた2つのdriver timeoutは不受入原本に残す。最終頁callbackF21D/delay0を確認してから別の復帰Aを押す。ROM文言を変更していない。
