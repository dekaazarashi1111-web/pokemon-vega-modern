# Stage82 native Move Memory archive UI

The exact Stage81 candidate is retained as parent. The new candidate repairs two
actual Stage75 archive entry gates and the Japanese native relearner allocation,
menu item/name storage and name-stride consumers. Six guarded spans change 317
bytes. The original HOF flag remains mandatory. Existing adopted moves, archive
prices, Stage62 and historical Stage79/81 evidence are not changed.

`tools/modernization_p03_archive_ui_repair.py --verify-assembly` requires the
reviewed Thumb source to assemble to exactly the pinned 220-byte native function.
The scheduler's selected-party/slot and move-ID offsets do not move. Forty moves
plus cancel receive distinct item and 16-byte name storage inside the expanded
allocation. No expected output ROM hash is derived from an unreviewed compiler.

`run_modernization_p03_archive_ui_e2e.py` runs 25 new processes: four replacement
slots, first/last entries on all four machine pages, tutor first/last, empty-slot
learning, teach refusal, summary/list/page/mode cancellation and pre-HOF denial.
Every case saves through the Start menu, destroys the original core, then uses
normal Continue on a new core and checks all four moves and PP, level, species,
HOF state, item retention and save counter. Three observed phases prohibit all
seven mCore host-write APIs. Mon/item/HOF state are isolated pre-input fixtures;
these tests do not establish natural mon acquisition, breeding or every P03 path.

The fixed mGBA 0.10.2 RTC writer can remap flash without rebinding currentBank.
Before observation, the private RTC trailer is reserved and the bank pointer is
rebound while proving every one of the 131072 game-flash bytes is unchanged.
RTC, both save banks and native saving remain enabled. No host writes are made
inside the guarded learning, saving and fresh-Continue observations.

Two separately reported negative controls use Stage81 and a gate-only repair.
The latter reproduces the exact illegal opcode at 081c7a60 (0000efff), followed
by the selected-party corruption assertion. This is failure evidence, never a
successful runtime case. Candidate successes require zero emulator warnings.

The Stage82 adapter preserves the complete Stage79 seven-domain validators and
composes the exact child recipes only at the candidate validation boundary.
Separate state roots prevent old candidate cache reuse. The matrix performs
seven fresh processes; merging validates/reuses those seven receipts and does
not perform another seven. Historical merged gates are restored byte for byte.

`python3 scripts/record_modernization_stage82_archive.py`. This addendum records
the above closed archive conditions; the prior comprehensive acceptance record
