# 育成・操作QOL実装方針

## 1. 目的と優先度

Vega本編、DPE/CFRU統合、二地方化と同じrelease scopeで、現代的な育成機能と高速な操作感を実装する。添付仕様にある機能は削らず、次の順で縦切りする。

1. **QOL-A（T10までの必須コア）**: 移動高速化、即時文章、全体学習装置、現代孵化、経験アメ、複数使用UI、育成道具、IV/EV表示、タマゴPC転送、孵化演出設定。
2. **QOL-B（T17の回帰前に統合する高度機能）**: PC検索・複数選択・一括操作、フィールドPC、PC内の技・持ち物操作、タマゴバスケット、自動戦闘。T13の最初のカントー往復を待たせないが、release scopeからは外さない。
3. **供給・進行（T12/T15/T16）**: 各機能を本編進行、D・Hビル、Vega殿堂入り、カントーリーグへ結び付ける。
4. **回帰・配布（T17/T18）**: 全checkpoint、save/load、操作説明、既定設定を固定する。

上流に同名機能があるという記述だけでは実装済みとみなさない。T01/T02で固定commitのconfig、hook、save依存を確認し、利用できる実装は再利用し、Vegaと合わない境界だけadapterまたは再実装する。

### 1.1 UI・イベントの最小実装原則

- 機能を優先し、新しいfull-screen UI、window skin、専用animation、装飾asset、複雑な画面遷移は原則追加しない。
- 既存のsummary/PC右欄、標準list menu、数量選択、Yes/No、文字入力、技思い出し、PC、Optionsを再利用する。収まらない設定だけ既存list部品の簡易 `QOL設定` を1枚使う。
- IV/EVは新規専用pageを作らず、summaryの既存情報欄とPC右欄をSELECT/L/Rで切り替える同一のcompact text rendererにする。barや新規graphは必須にしない。
- 複数使用は既存数量選択、検索は標準list＋既存文字入力、複数選択は既存PC上の簡易marker、技変更は既存技思い出し画面、field PCは既存PC画面をそのまま開く。

## HMフィールド能力

- Vega既存HM01〜08をバッグに所持した時点で、対応能力を解禁する。HM05はフラッシュ、HM08はダイビングとする。
- badge、手持ち数、技習得、習得適性、空き技枠は解禁条件にしない。HMを忘れても能力は失わない。
- HMは消費せず、save fieldやstory flagを新設せず、save/load後もバッグ所持から導出する。
- map、地形、向き、Surf状態、follower、実行中scriptの既存安全境界は維持する。技を一時的にもポケモンへ書き込まない。
- QOL解禁eventは、原則として既存NPCまたは端末への短い会話、条件check、flag、道具/機能解禁だけで完了させる。専用map、長いcutscene、escort、minigame、複数段階の演出は作らない。
- 「quest」は既存進行flag・捕獲数・所持条件を1回確認して報酬を渡す簡易依頼を意味する。カントー預かり屋依頼、D・H端末、タマムシ研究NPCもこの形に統一する。
- 元Vega/FireRedに既にある地形仕掛けやgym puzzleは再利用してよいが、新規追加eventの演出規模は `SIMPLE_EVENT` を既定にする。

## 2. 高速操作の既定値

### 2.1 移動

- ダッシュはVega基準の同一路程を**25%以上短時間**で移動できるようにする。
- 自転車はVega基準の同一路程を**50%以上短時間**で移動できるようにする。
- 歩行、NPC、強制移動、段差、warp、接触scriptの意味は変えない。速度定数と更新処理はT02で特定し、T10の `config/feature_matrix.csv` で固定する。
- 高速移動でもtileを飛び越えず、各tileの歩数、遭遇、毒、孵化、接触・座標eventを本来の順で1回だけ処理する。
- T10でVega基準と統合版を同じ100 tile直線、曲がり角、接触script、warp/段差混在courseでframe計測し、`tests/fixtures/qol_movement_courses.json` に固定する。

### 2.2 文章

- 新規saveと設定fieldを持たない移行saveの既定は `TEXT_SPEED=INSTANT` とする。
- 通常会話、看板、取得通知、店、PC、メニュー説明、戦闘messageは人工的なglyph間delayを0にし、次の描画機会でページ内の文章を即時表示する。
- 変数展開、色、改行、改ページ、選択肢、明示wait、効果音などの制御codeは順序を維持する。選択肢や改ページを自動決定・自動送りしない。
- NPC移動、fade、camera、battle開始・終了など、文章とは別の同期処理は短縮しない。
- `INSTANT / FAST / NORMAL` を選択可能にし、変更値はsaveへ保持する。

## 3. 現代式孵化

- かわらずの石: 片親なら所持親の性格を確定継承、両親ならどちらか一方。同じ全国図鑑番号の通常・リージョンフォーム間では所持親の姿を継承する。
- あかいいと: 重複しない5能力分のIVを両親から継承する。
- パワー系6種: 対応IVを確定継承し、あかいいと併用時は合計5能力に含める。
- 父母双方のタマゴ技、両親共通level技、ボール、通常特性slot、おこうbaby、メタモン、リージョンフォームを処理する。
- 隠れ特性は母親、またはメタモンでない親を基準に60%で継承する。
- 異なる親IDの組合せでは色違い判定を合計6回、同じ親IDでは1回行い、最初に成立した個体を採用する。
- 手持ち満杯時は確認後に最初の有効なPC空slotへ直接送る。全box満杯なら個体を生成・消費せず明示する。
- 預かり屋は生成順を保持した最大5個のタマゴqueueを持ち、手持ちとPC容量の範囲でまとめて受け取れる。
- 孵化演出は `NORMAL / FAST / SKIP`、既定は `FAST`。`SKIP` でも図鑑登録とニックネーム確認を省略しない。
- まるいおまもりは `species_ids` の `is_official=true` かつ異なる `canonical_national_dex` を100種捕獲、またはカントー預かり屋quest完了の早い方で解禁する。フォームは同じ全国番号として1種に数える。所持中は通常のタマゴ生成check成功率を2倍（上限100%）にし、check間隔や生成個体の内容は変えない。

## 4. 経験アメと共通複数使用UI

| 道具 | 加算経験値 |
|---|---:|
| けいけんアメXS | 100 |
| けいけんアメS | 800 |
| けいけんアメM | 3,000 |
| けいけんアメL | 10,000 |
| けいけんアメXL | 30,000 |

- 5種はVega既存Item IDを移動せず末尾の予約rangeへ追加し、名称、説明、icon、palette、pocket、価格、使用callbackを生成する。
- 共通callbackで選択した1匹だけへ固定経験値を加算する。努力値は増やさず、全体学習装置へ分配しない。
- 複数levelを跨ぐ時も1 levelずつ順番に進め、各levelの技習得、能力再計算、進化機会を落とさない。
- Lv.100または採用level capで停止し、overflow、効果なし時の消費を起こさない。
- 数量UIは `x1 / x5 / x10 / すべて`。経験アメ、栄養drink、ハネ、ふしぎなアメ、テラピース、coin系、努力値reset用品で共通利用する。

## 5. 育成値・変更機能

### 5.1 ジャッジ表示

- ゲーム開始時から、手持ちsummaryの既存情報欄をSELECT/L/RでIV/EVへ切り替える。タマゴも数値を表示する。
- IVは実数と6区分の判定語（31=`さいこう`、30=`すばらしい`、26–29=`すごくいい`、16–25=`かなりいい`、1–15=`まあまあ`、0=`ダメかも`）を併記する。
- EVは各能力の数値・MAX表示と、合計 `x / 510` をcompact textで表示する。既存欄に無理なく収まる場合だけ短いbarを併記する。
- PC右欄も同じrendererを使い、SELECTで通常/ジャッジ、L/RでIV/EVを切り替える。

### 5.2 ミント・特性・王冠・努力値reset

- ミントは元性格を維持し、別field `natureMint` で能力補正だけを変更する。孵化は元性格を継承する。
- 特性カプセルは通常slot間、特性パッチは隠れ特性への変更に使う。無効対象では消費しない。
- 王冠はSV式Hyper Trainingとする。ぎんは選択した1能力、きんは6能力を「きたえた！」にし、実IVを変更しない。戦闘能力計算では31相当、孵化では元IVを使い、表示は実IV31と区別する。
- 努力値reset後は各EV、合計、実能力値を即時再計算する。
- 単能力reset用品は対応する1能力だけを0、D・H研究端末の無料 `EV_RESET_ALL` serviceは6能力を0にする。どちらも実行前に確認し、効果なし時は道具・料金を消費しない。
- 1個目badge後にだいじなもの「わざメモリー」を配布し、手持ちの通常技思い出し・技忘れを無料化する。既存のシオウ・カラスバNPCも同じcoreを使い、キノコを消費しない。
- タマゴ技はD・Hビル攻略後に解禁する。殿堂入り前はものまねハーブ所持と空き技枠を要求し、殿堂入り後は無料にする。ハーブは消費しない。

### 5.3 全体学習装置

- 1個目badge後に解禁し、既定ONとする。バッグまたは設定からON/OFFを切り替え、状態をsaveする。
- ON/OFFは戦闘経験値の分配だけを変え、経験アメや他のfield-use経験値へ介入しない。

## 6. PCと高度QOL

- 物理PCでは最初から、標準list menuによる名前・タイプ・特性の単独/複合検索と、SELECT markerによる複数選択を使える。専用検索画面は作らない。
- box間一括移動は容量不足時に一部だけ変更せず、操作全体を戻す。一括逃がしはタマゴ、`NO_RELEASE` 個体、mail/key系持ち物の個体を選択不可にする。通常の持ち物は先にbagへ戻し、bag容量不足なら全処理を戻す。捕獲済みflagや共有特殊捕獲stateは変更しない。
- `content` のmap schemaへ `field_pc_allowed` を追加する。D・Hビル攻略後、trueの町・道路だけfield menuからPCを開け、未設定はfalseとする。battle、実行中script、gym、dungeon、league、event専用mapでは開かない。
- PC内の技変更は2個目badge後の無料技思い出しpool（既習得level技とrelearn登録技）だけを対象にし、任意のTM/tutor/egg技を付与しない。採用技のPPを正しく初期化する。
- PC内の持ち物一括操作はD・Hビル攻略後に解禁し、mail/key系を対象外にする。bag/box容量不足時は複製・消失させず全処理を戻す。
- タマゴバスケットはカントー預かり屋quest後、`field_pc_allowed=true` のmapで標準field menuから簡易ON/OFFできる。預かり屋に現在登録されている2匹を親とし、有効中は256歩ごとに通常の相性・生成RNG・孵化coreを1回呼び、預かり屋と共有する最大5個queueへ生成する。同じmenuから表示・受取でき、queue満杯、親不在、相性なしでは生成しない。専用picnic画面、親選択画面、専用animationは作らない。
- 自動戦闘はD・H研究端末で解禁する。任意の通常random野生戦だけで選択でき、trainer、static/story/legend、色違いでは通常戦闘へ戻す。捕獲・bag itemは使わず、通常battle coreでPP、status、faint、経験値、EV、全体学習装置を処理し、開始前と各turnにcancelできる。

## 7. 解禁と供給

| 境界 | 解禁・主な供給 |
|---|---|
| 最初から | IV/EV表示、即時文章、移動高速化、物理PCの検索・複数選択・一括移動/逃がし、孵化演出設定 |
| 1個目badge後 | 全体学習装置ON、かわらずの石、タマゴPC直接転送、わざメモリー（通常思い出し・技忘れ） |
| 預かり屋の初回利用時 | 最大5個のタマゴqueueとまとめ受取 |
| 2個目badge後 | PC内技変更 |
| D・Hビル攻略後 | わざメモリーのタマゴ技、アメXS/S、アメM初回報酬、特性カプセル、一部mint、全EV reset service、field PC、持ち物一括操作、自動戦闘 |
| カントー預かり屋quest後 | あかいいと、タマゴバスケット、まるいおまもり（100種捕獲でも可） |
| 5個目badge後 | パワー系道具 |
| 6個目badge後 | アメM反復入手 |
| 7個目badge後 | アメL、ぎんのおうかん |
| 8個目badge後 | 特性パッチ限定入手、全mint、単能力EV reset用品、標準育成品の無制限店売り |
| Vega殿堂入り後 | わざメモリーのタマゴ技無料化、アメXL |
| カントーリーグ後 | アメXL反復入手、きんのおうかん |

XS/Sは落とし物・調査・一般再戦、Mはgym・D・H研究依頼・高rank再戦、Lは高難度dungeon・カントーgym・raidを主経路にする。XLはVega殿堂入り時に一度だけ入手し、カントーリーグ後にraid・Battle Factory・BP交換で反復入手を解禁する。あかいいとはカントー預かり屋依頼、一部mintはタマムシ方面の研究NPCへ置く。標準育成品の無制限店売りは8個目badge後、L/XL・王冠・特性パッチの反復供給は表の専用境界を守る。

## 8. タスク割当と完了判定

| タスク | 担当 |
|---|---|
| T01/T02 | 上流機能、Vega hook、速度、文章、経験値、預かり屋、PC、save領域の実証 |
| T05/T06 | 道具ID・callback、経験値分配、能力計算、特性、Hyper Training |
| T08/T09 | 永続state、現代孵化、learnset、summary/PC、タマゴqueue |
| T10 | QOL-Aを1 saveで動かす統合vertical slice |
| T12/T15/T16 | 記号unlock、進行条件、配置、経済、反復報酬 |
| T17 | QOL-Bを統合してQOL-A/Bと全checkpointを回帰 |
| T18 | 設定説明、操作方法、release既定値 |
| T19 | 過去のfixture/probe判定を再監査し、35機能を実ユーザー導線へproduction接続 |

release候補は、固定RNGの孵化matrix、経験アメ境界、IV/EV表示境界、育成道具、box満杯、PC一括操作、移動event、全文字制御code、新規/移行saveの全試験を通過しなければならない。具体的なsmoke IDは `tests/smoke_test_matrix.csv`、詳細戦略は `docs/TEST_STRATEGY.md` を正とする。

T19では`release_default=ENABLED`、host fixture、生成table、ROM probeだけを完成証拠にしない。35機能すべてについて、通常プレイの実入口、production callback、unlock/save owner、実入力mGBA caseを一意に固定し、未接続分類を0にしてから完成とする。
