# 00 採用仕様 V2 ― ベガ本編＋クリア後カントー＋二地方生態

## 1. 最終的に作るゲーム

本設計の完成形は、**ベガを本編・世界観・既存ポストゲームの正本として残し、初回殿堂入り後にファイアレッド原作のカントー地方を追加する**構成である。

```text
ゲーム開始
  ↓
ベガ本編を既存どおり攻略
  ↓
初回殿堂入り・全国図鑑
  ↓
クチバ港行きの連絡船を解禁
  ↓
高レベル化したカントー地方で8つの「認定章」を取得
  ↓
カントーリーグ
  ↓
ハナダのどうくつとスフィアいせきを結ぶ二地方共鳴編
```

カントーでは原作FRの地形、NPC座標、ジム内装、主要施設、一部イベント演出を再利用する。原作ストーリーを最初から再演するのではなく、トーホクチャンピオンが共同生態調査へ招かれた後日談として作り直す。

## 2. 今回の追加条件

前版からの最大の変更は、追加公式ポケモンをカントーへ隔離しないことである。

- 全国図鑑No.1～1025を541進化系統として管理。
- **541系統すべてにトーホク側とカントー側の両方の入手導線を設定。**
- 通常系統の基礎種は原則として両地方で捕獲可能。
- 進化後は進化入手を基本とし、殿堂入り後DexNavや高難度地域だけで中間進化を希少配置。
- 伝説・幻・UB・パラドックスは重複個体を作らず、主捕獲地方と副地方の手掛かりイベントに分ける。
- ベガ既存の野生枠、1%枠、固有種、配布、固定イベントは削除しない。
- ベガ固有ポケモン181種はトーホクの個性として保護し、カントーでは研究交換・施設戦など限定的に扱う。

## 3. 二地方の役割差

| 地方 | 主な役割 | レベル | 入手上の価値 |
|---|---|---:|---|
| トーホク | 本編中の低～中レベル捕獲、育成開始、自然な初見 | Lv.2～66、本編後は～90 | 早期育成、進化前の確保、ストーリーに沿った生態イベント |
| カントー | 殿堂入り後の高レベル再捕獲、隠れ特性、タマゴ技、進化素材 | Lv.68～100 | 即戦力、DexNav厳選、進化道具、認定章報酬 |
| 二地方共通 | 大量発生、研究交換、固定イベント、図鑑評価 | 可変 | 片方で取り逃しても詰まない救済 |

「両方で出る」を単なる重複にせず、トーホクでは育成用、カントーでは完成個体の再捕獲用にする。

## 5. 絶対に守る互換ルール

1. ベガIPSとファクトリーUPSを順番に重ねて完成とはしない。
2. ベガ適用ROMを母体にし、CFRU/DPEの機能をソース・バイナリ監査しながら再移植する。
3. カントーマップは原作マップ番号へ戻さず、新規マップグループに複製する。
4. カントーの認定章はベガのバッジフラグと完全に分離する。
5. カントー原作のオーキド、ロケット団、シルフ、ふえ、ひでんマシン等の進行フラグを再利用しない。
6. SaveBlock、PC、図鑑、フォーム、捕獲済みフラグを拡張してからイベントを入れる。
7. 通信、リアルタイム待ち、外部配布を図鑑完成の必須条件にしない。
8. ROM本体は配布せず、クリーンBPRJ Rev.0向けの単一差分パッチだけを最終成果物にする。

# 01 技術統合・競合回避 V2

## V2で追加された技術要件

### 1. カントーは「復元」ではなく新規マップ群として挿入

ベガROM内の元FRマップ番号へ原作データを上書きしてはいけない。ベガが同じマップID、スクリプトID、ワープ、フラグ、タイルセットを別用途で使用している可能性があるため、クリーンBPRJ Rev.0から抽出したカントー資産を次のように扱う。

```text
原作FRマップ資産
  ├─ blockdata / border / connections
  ├─ object events / warp coordinates
  ├─ tileset references
  └─ visual scripts
          ↓
統合版の新規マップグループ KANTO_POSTGAME
          ↓
新規マップヘッダ・新規イベントスクリプト・専用フラグへ再参照
```

再利用するのは地形、NPC座標、ジム仕掛け、建物構造であり、原作のストーリーフラグとトレーナーIDは再利用しない。

### 2. 野生出現は二つの実装方式を使い分ける

#### トーホク

```c
if (IsImportedEcologyUnlocked(map))
{
    if (RollOverlayRate(map, storyStage))
        species = ChooseImportedEcology(map, time, method, rotation);
    else
        species = ChooseOriginalVegaEncounter(map);
}
else
{
    species = ChooseOriginalVegaEncounter(map);
}
```

既存表をリポイントして新種を直接書き込む方式は採らない。これによりベガの1%枠、固有種、攻略上の入手順を保護する。

#### カントー

カントーは新規マップ群なので、12枠陸上表、5枠水上表、10枠釣り表を新規作成できる。ただし原作らしさを保つため、各通常マップで原作系統を最低4枠、比率35～60%残す。

### 3. 地方間で共有するデータ

| データ | 共有方法 |
|---|---|
| 捕獲・見つけた図鑑 | 全国図鑑フラグを共通使用 |
| 伝説捕獲済み | `FLAG_SPECIAL_xxxx_CAUGHT`を地方共通 |
| 大量発生 | 地方ごとに現在地を持つが更新カウンタは共通 |
| 研究ランク | ヒイラギ・オーキド両研究所で同じ値を参照 |
| カントー認定章 | ベガバッジとは別の8フラグ |
| 固定戦再戦受付 | シオンの救済NPCとヒイラギ研究所から同じ再戦キューを参照 |
| 進化素材製造 | BP・研究ポイント残高を共通使用 |

### 4. 最低限必要な専用領域

- カントー47地点分のマップヘッダ、イベント、ワープ、接続
- トーホク追加抽選テーブル49地点
- カントー野生テーブル47地点
- 541系統×2地方の配置参照
- 34イベント分のフラグ・変数・スクリプト
- カントー認定章8フラグ
- 伝説等125種の捕獲済み共有フラグ
- NPC再利用26件、重要アイテム置換24件
- ジム・再戦96体分のトレーナーデータ

## 前版から継承する競合分析


## 1. 単純な二重適用を禁止する理由

ファクトリーUPSはクリーンな日本語版ファイアレッドを前提に、元ROM内へフックとポインタを書き、32 MiB拡張領域へCFRU/DPEのコード・表・画像・鳴き声を置く。一方ベガIPSは同じ土台のコード、データ表、マップ、スクリプト、種族領域を独自に変更している。

解析結果は次のとおり。

| 項目 | 値 |
|---|---:|
| ファクトリーUPS元サイズ | 16,777,216 bytes |
| ファクトリーUPS先サイズ | 33,554,432 bytes |
| UPSセグメント数 | 664,194 |
| UPS XOR非ゼロ総量 | 14,680,526 bytes |
| 拡張16 MiB側の非ゼロ量 | 14,667,339 bytes |
| ベガIPSレコード数 | 20,195 |
| ベガIPS書込量 | 3,782,136 bytes |
| 先頭16 MiBの直接重複 | 775 bytes／269区間 |
| 最大連続重複 | 36 bytes |

`IPS→UPS`、`UPS→IPS`のどちらも、後から当てたパッチが先のフックやデータ表を部分的に壊す。したがって「パッチ結合」ではなく、**ベガをベースにDPE/CFRUのソースを再ビルドする移植**として扱う。

## 2. 正しいビルド順

1. クリーンなBPRJ Rev.0へベガIPSを適用し、ベガ作業ROMを作る。
2. 作業ROMを32 MiBへ拡張する。`0x01000000`以降は一旦`0xFF`またはビルドツールの想定値で初期化する。
3. ベガの種族、技、道具、特性、グラフィック、鳴き声、図鑑、野生、トレーナー、スクリプト、フラグ、SaveBlockを抽出する。
4. DPE-JPを先に移植し、DPEの全表を「ベガ既存IDを先頭に保持する構造」へ変更する。
5. CFRU-JPを後から移植し、全フックをベガROMの実アドレスへ再解決する。
6. ベガの既存イベントとトレーナーを新エンジンへ接続する互換層を入れる。
7. 外来生態、ショップ、イベント、ギミックを追加する。
8. 最終的にクリーンBPRJ Rev.0を対象とするBPS/UPSを生成する。

DPE-JPのREADMEも、DPE適用後にCFRU-JPを適用する前提を明記している。ただし、既改造ROMであるベガへそのまま`make.py`を実行してよいという意味ではない。`bytereplacement`、`hooks.s`、`repointall`、SaveBlock参照を個別監査する。

## 3. 種族ID設計

### 禁止事項

- 全国図鑑No.を内部種族IDとしてそのまま使う
- DPEの`SPECIES_BULBASAUR=1`等をベガへ上書きする
- 同じ公式ポケモンを「ベガ版」と「DPE版」の2種族に分ける
- ベガ固有種をDPEの公式種で置換する

### 採用構造

```text
InternalSpeciesId (16bit)
├─ VEGA_NATIVE_xxx      ベガ既存の公式種205
├─ VEGA_FAKEMON_xxx     ベガ／AS系オリジナル181
├─ NATIONAL_EXT_xxxx    ベガ未収録の公式種820
└─ FORM_EXT_xxxx        種族IDが必要な恒常・戦闘フォーム

NationalDexNo (0..1025)
TohokuDexNo   (0..386)
FormId        (別テーブル)
```

既存ベガ内部IDはROMから抽出するまで数値を確定しない。`data/ベガ既存図鑑ID保護台帳_386種.csv`のシンボルを先にコードへ導入し、数値の直書きを減らす。

### DPE公開基準のID容量と再配置

調査時点で固定したDPE-JP公開基準では、通常種・フォーム・内部補助種を含む定義が `SPECIES_PECHARUNT=0x59F`、`NUM_SPECIES=0x5A0` まで伸びている。ただし、この数値並びをベガへそのまま持ち込まない。ベガ既存386枠を固定したうえで、未収録公式820種、独立IDが必要な能力差フォーム、CFRU/DPE内部補助IDの順に再採番する。

- 全国図鑑1025種と内部種族ID総数は一致しない。
- 外見差だけのフォームは基礎種ID＋`FormId`とし、種族IDを浪費しない。
- `SPECIES_SHADOW_WARRIOR`等の補助IDは図鑑、野生、育て屋、PC検索から除外する。
- DPE元IDと統合後IDは `templates/species_id_map.csv` で双方向に追跡する。

| 対象 | 正本 | 統合方法 |

## 5. フック監査

CFRU/DPEの全パッチ点を、以下の四分類でCSV化してから移植する。

1. **安全な純粋フック**：元命令列がベガでも一致し、処理だけ拡張領域へ飛ばす。
2. **要ラッパー**：ベガが同じ関数を改変している。両方の処理を呼ぶラッパーを新設。
3. **再実装**：ベガ固有の関数へCFRUロジックを手作業で統合。
4. **無効化**：追従や着せ替え等、初期版で採用しない機能のフック。

各フックは、元アドレス、期待バイト列、ベガ実バイト列、上書き長、復帰先、使用レジスタ、破壊フラグ、関連SaveBlockを記録する。期待バイト列が一致しないフックを自動適用してはいけない。

## 6. 32 MiB領域とリンク

ファクトリーUPSは拡張側に約13.99 MiBの非ゼロデータを持つため、残容量は大きくない。既存ファクトリーの後半16 MiBをそのままコピーする方式は採用しない。ベガとDPEの重複公式種205体の画像・鳴き声・表を一つにまとめ、重複資産を削減してリンクし直す。

推奨ルール:

- コードと読み取り専用表はリンカスクリプトで自動配置
- 画像・鳴き声・アニメは重複排除ハッシュを通す
- 末尾に64 KiB以上のビルド情報・将来拡張予約を残す
- `offsets.ini`とmapファイルを必ずリリースへ同梱
- ROMポインタは`0x08000000 + file_offset`を一元マクロ化

## 7. SaveBlock

1025種の見た／捕まえた、DexNav検索レベル、フォーム、研究ランク、進化カウンタ、レイド状態、拡張PCを追加するため、SaveBlockの再設計が必要。

- ベガ既存フラグ・変数・所持品・図鑑・PCの配置を先に解析
- CFRU既定のSaveBlockアドレスをそのまま使用しない
- セーブに構造バージョンとCRCを付ける
- v1.0は**新規ゲーム必須**を標準とする
- 旧ベガセーブ移行は別ツールで、主人公・手持ち・PC・進行フラグの限定変換とする
- セーブ読込失敗時に初期化せず、エラー画面とバックアップ復元を出す

## 8. テキスト・日本語UI

- 4桁図鑑番号、HP4桁、長い特性・道具名、6文字以上のポケモン名を全画面で検証
- ベガ固有名を短縮しない
- 同名公式種は一つの文字列IDに集約
- フォーム名は図鑑詳細だけで表示し、戦闘名欄を溢れさせない
- 改行制御、全角記号、性別記号、濁点、長音の幅を画面別に試験

# 02 二地方の世界観・進行・解禁

## 1. 設定

追加種の存在は、別作品のストーリーをベガへ被せず、次の一本で説明する。

> D・H団がスフィア由来の波動と各地方の転送データを観測した結果、トーホクの生態境界が弱まり、従来確認されなかったポケモンが少数定着した。殿堂入り後、ヒイラギ研究所はオーキド研究所、シルフ、ニビ博物館と共同調査を開始する。

本編中の新種は「以前からいたが非常に少なかった個体」「D・H設備や海流に迷い込んだ個体」として扱う。伝説・UB・パラドックスだけは、スフィアいせきとカントー側の転送事故が起きるポストゲームまで出さない。

## 2. 進行タイムライン

| 進行 | 主地方 | 新しい生態・イベント | 保護・制限 |

| ゲーム開始～アヤメ | トーホク | 新種4～7%追加抽選。パモ、ヤヤコマ、ホシガリス等 | 既存ベガ野生表を100%保護 |

## 3. カントーへの移動

初回殿堂入り後、ヒイラギ研究所で `K-E01 二地方共同調査の出航` を開始する。

1. 全国図鑑と「カントーちょうさパス」を受け取る。
2. アーシア島または新設港から連絡船に乗る。
3. 船上の短いダブルバトルでカントー向けレベル帯を提示する。
4. クチバ港到着後、トーホクへいつでも戻れる。
5. カントーの8ジムはベガのバッジではなく「認定章」を授与する。
6. 認定章は通行、施設、野生表、ジム再戦にだけ使い、秘伝技・命令レベル・ベガ本編フラグには接続しない。

## 4. 研究ランク

| ランク | 条件例 | 解禁 |
| --- | --- | --- |
| 0 | バッジ1またはT-E01完了 | 基本DexNav、追加抽選、二地方図鑑表示 |
| 1 | 新種30種捕獲＋調査3件 | 大量発生、追加ボール、夜間固定チケット |
| 2 | 新種100種捕獲＋調査10件 | 隠れ特性、進化道具店、カントーサファリ更新 |
| 3 | 新種250種捕獲＋カントー認定章4個 | 化石全種、御三家タマゴ再取得、特性カプセル |
| 4 | 新種500種捕獲＋カントーリーグ | UB・幻の大半、特性パッチ、レイド高難度 |
| 5 | 新種800種捕獲＋スフィア遺跡＋二地方共鳴 | パラドックス、テラパゴス、最終図鑑報酬 |

捕獲数だけでランクを上げると作業感が強くなるため、固定イベント、進化、孵化、DexNav、サファリ、レイドをポイント化する。片方の地方だけを集中的に遊んでもランク3までは到達でき、最終ランクだけ二地方の主要イベントを要求する。

## 5. 両地方を回る意味

### トーホク側の利点

- 新種を低レベルから育てられる。
- ベガ本編のジム・D・H団・四天王へ新種を連れて行ける。
- 地形に沿った固定イベントで進化素材を早めに得られる。
- 殿堂入り後の既存拡張エリアへ新しい調査理由が生まれる。

### カントー側の利点

- Lv.68～100の即戦力を捕獲できる。
- DexNavで隠れ特性、タマゴ技、高個体値を狙える。
- 進化道具、ミント、メガストーン、テラピースを認定章報酬と施設で入手できる。
- FR原作の施設やイベント構造が、新世代要素のチュートリアルとして機能する。

## 6. 取り逃し防止

- 通常系統は両地方のどちらか一方だけで進化系統を完成できる。
- 片方の出現イベントを逃しても、もう片方の野生、DexNav、タマゴ、復元、研究交換で補える。
- 夜限定種は生態チケットで時間帯を固定できる。
- 大量発生はRTCだけに依存せず、歩数または殿堂入り更新でも切り替えられる。
- 固定個体を倒した場合、ヒイラギ研究所またはシオンの救済NPCで再戦登録する。
- 交換進化は「つながりのヒモ」、特殊操作進化は回数・場所・道具へ変換する。

## 7. 既存ベガポストゲームとの関係

カントーは既存のエリア調査、三島、スフィアいせき、ミラージュバトルを置き換えない。初回殿堂入り後に並行して選べる別ルートとする。

```text
殿堂入り後
  ├─ ベガ既存エリア調査
  ├─ トーホク全国生態保護区
  ├─ カントー認定章巡り
  └─ ミラージュ／ファクトリー
          ↓
いずれも進めると二地方共鳴編へ収束
```

# 03 トーホク地方 ― 新種出現・イベント詳細

## 1. トーホク側の基本方針

トーホクはベガ本編の舞台なので、**既存野生表を正本として保持し、その前段に追加抽選を置く**。既存の通常枠、低確率枠、固有種、イベント個体を置換しない。

### 本編中

- 序盤の追加率は4～7%、中盤は5～10%、終盤は6～12%を上限とする。
- 1マップに通常出現させる新系統は最大6。
- 候補が多い地点はA/B/Cの3ローテーションへ分ける。
- ベビィ、600族、人工種、特殊フォームは通常草むらへ安易に入れない。
- 新種イベントを未完了のマップでは、該当系統を通常抽選しない。

### 殿堂入り後

- 同じマップへ高レベル再訪表を追加する。
- 新種比率を12～40%へ引き上げる。
- 中間進化をDexNav希少枠へ入れる。
- 最終進化はサファリ、裂け目、固定イベントを除き原則として進化入手にする。

### イベント実装上の原則

- 必須ストーリーのマップ移動を止めない。新イベントNPCは脇道、研究所、既存小部屋へ置く。
- イベント開始前に既存NPCやワープを消さない。
- 捕獲可能な固定戦は、倒す・逃げる・手持ち満杯・PC満杯を分岐試験する。
- 環境変化フラグは地方別に持ち、カントー到着だけでトーホク本編中の表が変わらないようにする。
- 本編中のイベント報酬は強すぎる対戦道具ではなく、進化素材、研究機能、捕獲補助を中心にする。

## 6. トーホクで新種を出しすぎないための上限

1. 通常道路の追加抽選は本編中10%以下。
2. 既存1%枠を新種へ置換しない。
3. 600族は通常歩行0%、DexNav1～2%または固定イベント。

5. 地域フォームは環境イベント、交換、孵化条件で説明できるものだけ配置。
6. 御三家は通常草むらへ入れず、研究タマゴと殿堂入り後サファリで扱う。
7. 伝説・UB・パラドックスは通常表0%。

## 7. 取り逃し救済

- 各通常系統にはカントー側の第二入手地点がある。
- T-E01～T-E14の固定個体を倒しても、イベント完了後は通常生態または研究交換が解禁される。
- T-E15の裂け目選択は一時的な順番選択であり、最終的には全候補へ再挑戦できる。
- T-E16の保護区は、通常配置から漏れた系統を日替わりで補完する。

# 04 カントー地方 ― クリア後マップ・出現・イベント詳細

## 1. カントーの位置付け

カントーはベガ初回殿堂入り後の高レベル地方であり、FR原作のストーリーを再演する場所ではない。

- マップ形状、NPC座標、ジム内装、施設、道路接続の見た目は原作準拠。
- マップ内部ID、スクリプト、フラグ、トレーナー、報酬、ワープ先は統合版専用。
- 主人公はすでにトーホクチャンピオンとして認知される。
- 8ジムは「バッジ」ではなくカントーリーグの適性を示す「認定章」を授与する。
- ロケット団本編、オーキドの最初のポケモン、シルフスコープ、ポケモンのふえ等は別目的の後日談イベントへ置換する。

## 2. カントー野生表の配分

カントーは新規マップ群なので野生表を全面再作成できる。ただし原作らしさを失わないよう、次を守る。

- 通常道路では原作系統を45～60%、新種を40～55%。
- 洞窟、水路、サファリ、研究施設では新種45～75%。
- ポッポ、コラッタ、イシツブテ、ズバット、コイキング、メノクラゲなど、その場所を象徴する系統を最低4枠または35%残す。
- Lv.68から始め、認定章と地理順にLv.100へ上げる。
- 進化前を通常枠、進化中間をDexNav、最終進化を固定戦・大量発生・進化入手へ分ける。

## 9. カントー側の取り逃し救済

- 重要イベントを先に終えても、野生表解禁だけ後から研究所で適用できる。
- トーホクですでに捕獲済みの伝説は、カントーでは捕獲不可の共鳴体または素材報酬へ切り替える。

# 05 二地方の入手設計・進化・特殊個体

## 1. 「全ポケモンを両地方に出す」の定義

生態として自然にするため、**全1025種をそのまま両地方の草むらへ並べることはしない**。代わりに次を保証する。

- 541進化系統すべてに、トーホク側とカントー側の二つの入手導線がある。
- 通常系統は両地方で基礎種を捕獲できる。
- 進化後は育成で入手でき、カントー高レベルDexNavや殿堂入り後トーホクで中間進化を補助的に捕獲できる。
- 御三家は両研究所のタマゴ、化石は両研究拠点の復元で入手できる。
- 伝説・幻・UB・パラドックスは捕獲個体を一体に限定し、もう一方の地方には手掛かり・共鳴戦・素材報酬を置く。
- フォルム専用内部ID、戦闘中フォーム、メガ、キョダイ、テラ状態は通常野生個体として扱わない。

7. 色違いロック、個体値、性格、持ち物、再戦レベルをイベントごとに明示する。
8. 全種を一つのROMで入手でき、外部配布・通信・期間限定を要求しない。

### 実効出現率の考え方

トーホクの「追加抽選5%」の中に6系統を均等配置した場合、各系統の実効率は約0.8%になる。新種の存在は感じられるが、既存表の1%枠を直接消さない。

```text
実効率 ＝ マップ追加抽選率 × 追加表内の個別重み
```

例：

```text
501番道路
追加抽選率 6%
  パモ 30%
  ヤヤコマ 25%
  ホシガリス 15%
  グルトン 10%
  夜枠 10%
  DexNav・条件枠 10%

パモ実効率：約1.8%
ヤヤコマ実効率：約1.5%
```

カントーは独立表なので、原作種と新種を同じ12枠へ置く。陸上枠の基本重みはFR系の20/20/10/10/10/10/5/5/4/4/1/1を踏襲しつつ、各マップの目的に合わせて原作種と新種へ配分する。

## 3. フラグ・変数の原則

- ベガ既存フラグ・変数の使用範囲をROMから抽出する。
- 「空いていそう」に見える番号を推測で使わない。
- カントー認定章、イベント、野生解禁、固定捕獲、再戦を名前付きレジストリへ登録する。
- 地方入場フラグと生態解禁フラグを分ける。
- 捕獲済み、イベント完了、報酬受取を一つのフラグへ詰め込まない。
- 変数の上位ビットを複数機能で共有しない。
- 開発ビルドではフラグ・変数値を閲覧できるデバッグNPCを用意する。

## 5. 野生表の統計検査

各マップについて10万回相当の乱数シミュレーションまたは決定論的な重み合計検査を行う。

- 枠重みの合計が100または期待する内部値。
- 本編中のトーホク追加抽選が規定上限以下。
- 既存ベガ表へのフォールバック率が正しい。
- カントーの原作系統比率が最低35%。
- 水上・釣り専用系統が草むらへ混入しない。
- 夜限定種に昼の救済導線またはチケットがある。
- 600族、伝説、UB、パラドックスの通常表混入がない。
- イベント解禁フラグ前後で候補が正しく切り替わる。

## 6. イベントの分岐試験

各捕獲イベントで次を実行する。

1. 通常捕獲。
2. 倒す。
3. 逃げる。
4. 敗北する。
5. 手持ち6体で捕獲する。
6. PCの対象ボックスが満杯。
7. PC全ボックス満杯。
8. 捕獲後に地方を移動。
9. 交換で先に図鑑登録した状態。
10. セーブ後ロードして再訪。
11. 殿堂入り更新で復活。
12. 副地方の共鳴イベントを先に完了。

## 7. リリース形態

最終的な配布物は次とする。

- クリーン日本語版ファイアレッドBPRJ Rev.0向け単一UPSまたはBPS。
- SHA-256付きmanifest。
- 変更履歴。
- 既知の不具合。
- セーブ互換性の明記。
- クレジット・ライセンス・非営利条件。
- ROM本体、他作品のROM、適用済みROMを同梱しない。

複数パッチを利用者に順番指定して重ねさせる形式は避ける。統合担当が一つの最終パッチを生成し、期待ROMハッシュが違う場合は適用を停止させる。
