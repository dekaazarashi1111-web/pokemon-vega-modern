# 00 結論と採用仕様

## 1. 完成像

完成版は「ベガのリメイク」ではなく、**ベガの物語・地形・イベントをそのまま遊べる拡張版**とする。初回エンディングまでの必須導線、ジム順、D・H団関連、ポケモンリーグ、スフィアいせき、ミラージュバトルシステムはベガを正とする。

追加するものは、全国図鑑No.1～1025のうちベガ未収録820種、必要な恒常フォーム、現代技・特性・道具・進化方法、図鑑ナビ、昼夜、大量発生、育成支援、終盤以降のメガシンカ等である。ベガには公式種205種とオリジナル種181種が既に存在するため、既存公式種をDPE側の同名種で二重登録しない。

## 2. 固定する七原則

1. **ベガの既存386枠を固定する。** 種族ID、トレーナー、野生、進化、図鑑、スクリプトの参照先を先に保護する。
2. **全国番号と内部IDを分離する。** `NationalDexNo=25` と `InternalSpeciesId=VEGA_NATIVE_025` は別概念。
3. **ストーリー完成条件を増やさない。** トーホク図鑑完成イベントは従来の386枠だけを見る。
4. **野生表を上書きしない。** 追加種は条件付きオーバーレイ、DexNav、大量発生、釣り、ずつき、岩砕き、保護区へ分散する。
5. **通信・RTC・マルチプレイを必須にしない。** 進化・出現には必ず単独プレイの代替手段を用意する。
6. **戦闘ギミックは段階解禁し、1戦1種類に制限する。** メガ、Z、ダイマックス、テラの同時使用は不可。
7. **配布物はパッチとソース差分だけにする。** ROM本体は配布しない。

## 5. パッチ解析の要点

- ファクトリーUPSは16 MiBのBPRJ Rev.0を32 MiBへ拡張する。UPSの対象CRC32は `3b2056e9`、生成物CRC32は `216ab7fd`。
- ベガIPSは20,195レコード、展開書込量 3,782,136 bytes、最大書込先 `0xFE28BC`。
- ファクトリー側は元の16 MiB内で 13,187 bytesを変更し、ベガIPSと直接重なるのは 775 bytes、269区間。
- 直接重複が少なく見えても、数バイトのBLフックやポインタ差替えが巨大な拡張コードへ分岐するため、互換性があることを意味しない。

# 01 技術統合・競合回避

## 1. 単純な二重適用を禁止する理由

ファクトリーUPSはクリーンな日本語版ファイアレッドを前提に、元ROM内へフックとポインタを書き、32 MiB拡張領域へCFRU/DPEのコード・表・画像・鳴き声を置く。一方ベガIPSは同じ土台のコード、データ表、マップ、スクリプト、種族領域を独自に変更している。

解析結果は次のとおり。

| 項目 | 値 |
|---|---:|
| ファクトリーUPS元サイズ | 16,777,216 bytes |
| ファクトリーUPS先サイズ | 33,554,432 bytes |
| UPSセグメント数 | 664,194 |
| UPS XOR非ゼロ総量 | 14,680,526 bytes |
| 拡張16 MiB側の非ゼロ量 | 14,667,339 bytes |
| ベガIPSレコード数 | 20,195 |
| ベガIPS書込量 | 3,782,136 bytes |
| 先頭16 MiBの直接重複 | 775 bytes／269区間 |
| 最大連続重複 | 36 bytes |

`IPS→UPS`、`UPS→IPS`のどちらも、後から当てたパッチが先のフックやデータ表を部分的に壊す。したがって「パッチ結合」ではなく、**ベガをベースにDPE/CFRUのソースを再ビルドする移植**として扱う。

## 2. 正しいビルド順

1. クリーンなBPRJ Rev.0へベガIPSを適用し、ベガ作業ROMを作る。
2. 作業ROMを32 MiBへ拡張する。`0x01000000`以降は一旦`0xFF`またはビルドツールの想定値で初期化する。
3. ベガの種族、技、道具、特性、グラフィック、鳴き声、図鑑、野生、トレーナー、スクリプト、フラグ、SaveBlockを抽出する。
4. DPE-JPを先に移植し、DPEの全表を「ベガ既存IDを先頭に保持する構造」へ変更する。
5. CFRU-JPを後から移植し、全フックをベガROMの実アドレスへ再解決する。
6. ベガの既存イベントとトレーナーを新エンジンへ接続する互換層を入れる。
7. 外来生態、ショップ、イベント、ギミックを追加する。
8. 最終的にクリーンBPRJ Rev.0を対象とするBPS/UPSを生成する。

DPE-JPのREADMEも、DPE適用後にCFRU-JPを適用する前提を明記している。ただし、既改造ROMであるベガへそのまま`make.py`を実行してよいという意味ではない。`bytereplacement`、`hooks.s`、`repointall`、SaveBlock参照を個別監査する。

## 3. 種族ID設計

### 禁止事項

- 全国図鑑No.を内部種族IDとしてそのまま使う
- DPEの`SPECIES_BULBASAUR=1`等をベガへ上書きする
- 同じ公式ポケモンを「ベガ版」と「DPE版」の2種族に分ける
- ベガ固有種をDPEの公式種で置換する

### 採用構造

```text
InternalSpeciesId (16bit)
├─ VEGA_NATIVE_xxx      ベガ既存の公式種205
├─ VEGA_FAKEMON_xxx     ベガ／AS系オリジナル181
├─ NATIONAL_EXT_xxxx    ベガ未収録の公式種820
└─ FORM_EXT_xxxx        種族IDが必要な恒常・戦闘フォーム

NationalDexNo (0..1025)
TohokuDexNo   (0..386)
FormId        (別テーブル)
```

既存ベガ内部IDはROMから抽出するまで数値を確定しない。`data/ベガ既存図鑑ID保護台帳_386種.csv`のシンボルを先にコードへ導入し、数値の直書きを減らす。

### DPE公開基準のID容量と再配置

調査時点で固定したDPE-JP公開基準では、通常種・フォーム・内部補助種を含む定義が `SPECIES_PECHARUNT=0x59F`、`NUM_SPECIES=0x5A0` まで伸びている。ただし、この数値並びをベガへそのまま持ち込まない。ベガ既存386枠を固定したうえで、未収録公式820種、独立IDが必要な能力差フォーム、CFRU/DPE内部補助IDの順に再採番する。

- 全国図鑑1025種と内部種族ID総数は一致しない。
- 外見差だけのフォームは基礎種ID＋`FormId`とし、種族IDを浪費しない。
- `SPECIES_SHADOW_WARRIOR`等の補助IDは図鑑、野生、育て屋、PC検索から除外する。
- DPE元IDと統合後IDは `templates/species_id_map.csv` で双方向に追跡する。

## 4. テーブル統合

各データは、単純コピーではなく次の手順で再構築する。

| 対象 | 正本 | 統合方法 |
|---|---|---|
| 種族基本値 | ベガ既存＋DPE | 既存386枠を抽出して先頭保持、未収録公式種を追記 |
| グラフィック／パレット | ベガ＋DPE | 既存ポインタを保持、DPE画像を拡張領域へ再配置 |
| 鳴き声 | ベガ＋DPE | 既存サンプルを保持し、追加分のみ挿入 |
| 技・特性・道具 | ベガ＋CFRU | 既存IDの効果を互換層で保持し、新規IDを後段追加 |
| 進化 | 統合CSV | 全553条件を一括生成し、通信等に救済を設定 |
| 図鑑 | 二層 | トーホク386＋全国研究1025＋フォームタブ |
| TM／教え技 | ベガ既存番号＋CFRU拡張 | 番号ごとの互換表を作り、既存入手イベントを維持 |

## 5. フック監査

CFRU/DPEの全パッチ点を、以下の四分類でCSV化してから移植する。

1. **安全な純粋フック**：元命令列がベガでも一致し、処理だけ拡張領域へ飛ばす。
2. **要ラッパー**：ベガが同じ関数を改変している。両方の処理を呼ぶラッパーを新設。
3. **再実装**：ベガ固有の関数へCFRUロジックを手作業で統合。
4. **無効化**：追従や着せ替え等、初期版で採用しない機能のフック。

各フックは、元アドレス、期待バイト列、ベガ実バイト列、上書き長、復帰先、使用レジスタ、破壊フラグ、関連SaveBlockを記録する。期待バイト列が一致しないフックを自動適用してはいけない。

## 6. 32 MiB領域とリンク

ファクトリーUPSは拡張側に約13.99 MiBの非ゼロデータを持つため、残容量は大きくない。既存ファクトリーの後半16 MiBをそのままコピーする方式は採用しない。ベガとDPEの重複公式種205体の画像・鳴き声・表を一つにまとめ、重複資産を削減してリンクし直す。

推奨ルール:

- コードと読み取り専用表はリンカスクリプトで自動配置
- 画像・鳴き声・アニメは重複排除ハッシュを通す
- 末尾に64 KiB以上のビルド情報・将来拡張予約を残す
- `offsets.ini`とmapファイルを必ずリリースへ同梱
- ROMポインタは`0x08000000 + file_offset`を一元マクロ化

## 7. SaveBlock

1025種の見た／捕まえた、DexNav検索レベル、フォーム、研究ランク、進化カウンタ、レイド状態、拡張PCを追加するため、SaveBlockの再設計が必要。

- ベガ既存フラグ・変数・所持品・図鑑・PCの配置を先に解析
- CFRU既定のSaveBlockアドレスをそのまま使用しない
- セーブに構造バージョンとCRCを付ける
- v1.0は**新規ゲーム必須**を標準とする
- 旧ベガセーブ移行は別ツールで、主人公・手持ち・PC・進行フラグの限定変換とする
- セーブ読込失敗時に初期化せず、エラー画面とバックアップ復元を出す

## 8. テキスト・日本語UI

- 4桁図鑑番号、HP4桁、長い特性・道具名、6文字以上のポケモン名を全画面で検証
- ベガ固有名を短縮しない
- 同名公式種は一つの文字列IDに集約
- フォーム名は図鑑詳細だけで表示し、戦闘名欄を溢れさせない
- 改行制御、全角記号、性別記号、濁点、長音の幅を画面別に試験

# 02 世界観・進行・イベント

## 1. 追加設定

追加種と戦闘機能は、ベガ本編へ別作品の物語を被せず、**D・H団がスフィア由来の波動を観測したことでトーホク地方の生態境界が緩んだ**という一本の設定で説明する。

- 本編中：ごく弱い「外来生態」が発生。研究所は調査を依頼するだけで、攻略必須にはしない。
- D・H団編後半：人工ポケモン、メガエネルギー、異常天候がD・H設備と結びつく。
- 殿堂入り後：スフィアいせきの安定化で全国生態調査が正式解禁。

# 03 野生出現・入手・進化

## 1. 全体方針

ベガの既存分布は、低確率1%枠や殿堂入り後の解禁まで含めて設計済みである。820種を既存11枠へ直接詰めると、ベガ固有種が消え、攻略Wikiとも一致しなくなる。そこで野生抽選を五層に分ける。

```text
A. ベガ基礎表           既存の草・水上・釣り・岩・木。無変更。
B. 外来生態オーバーレイ 条件成立時だけ5～12%で基礎抽選を差し替え。
C. DexNav隠し枠         通常歩行では0%、検索時だけ出現。
D. 大量発生             TV／スキャナで告知し20～40%。
E. 生態保護区           殿堂入り後のローテーション。チケットで任意固定。
```

これにより、ストーリー中の見た目はベガのまま、探せば新種がいる状態にできる。

## 2. 配置量の上限

- 1マップのストーリー中追加：基礎系統2、DexNav系統2、時間帯系統1まで

- 大量発生：同時1系統
- 生態保護区：1区画8～12系統
- 中間進化・最終進化は原則野生に置かない。例外は終盤1%またはレイド。
- 600族はバッジ7個以降または殿堂入り後。

## 5. 時間・天候・ローテーション

リアルタイム待ちは必須にしない。

- 通常時はRTCを使用。
- RTC未設定・電池切れでは12:00を既定値にし、研究所で時刻を選べる。
- 生態チケットを使うと、対象区画だけ朝・昼・夜・雨・雪・砂嵐をゲーム内1日固定。
- 週替わりではなく、入場時に選択できる「研究ローテーション」を用意。
- 季節限定種も、研究ランク到達後は保護区で常時選択可能。

# 05 トレーナー・施設・バランス

## 1. 本編初回戦はベガを正とする

ベガは高難度を前提に、固有種と既存種の役割、技構成、レベル曲線が組まれている。CFRUの現代AIや技仕様を入れるだけでも実質的に難化するため、初回本編では次を守る。

- トレーナーの種族、レベル、個体数は原則維持。
- 無効化された技、特性、道具だけ置換。
- 現代化で威力・命中・タイプが変わる技は全件監査。
- AIランクを一般トレーナー、エリート、ジム、幹部、四天王の5段階に分ける。
- 序盤AIには交代読み、確定数計算、ギミック使用を許可しない。
- 初回リーグではダイマックス・テラを使わせない。

# 07 イベント台本案

以下は既存マップへNPCまたは小部屋を足すだけで実装できる軽量イベント。コマンド名は疑似記法で、実際のXSE／CFRU special番号はID監査後に置換する。

## EVT-01 フィールドスキャナ

**場所:** ハクジ研究所  
**条件:** バッジ1個、未受取

```text
lock
faceplayer
msg "最近、見慣れない反応が出ている。草むらを変えるのではなく、
普段は姿を隠す個体を探す装置だ。"
giveitem FIELD_SCANNER
setflag DEXNAV_RECEIVED
setflag FOREIGN_ECOLOGY_ENABLED
special OPEN_DEXNAV_TUTORIAL
release
```

既存イベントの前後へ割り込ませず、研究所NPCの任意会話にする。

## EVT-02 生態チケット

**場所:** ミルシティ受付  
**条件:** スキャナ受取、調査3件

時間帯・天候を待たずに指定できる説明イベント。チケット使用時は対象エリアのローカル変数だけ変え、全世界のRTCを書き換えない。

## EVT-03 交換シミュレータ

**場所:** ハクジ研究所  
**条件:** バッジ4個

```text
choose_party_mon
if not_trade_evolution_target -> msg "今は反応しない"
if held_item_required and missing -> msg "必要な道具を持たせよう"
consume LINKING_CORD
special TRY_TRADE_EVOLUTION
```

実通信交換も残す。

## EVT-04 メガ実験停止

**場所:** D・Hビルの既存端末横  
**条件:** カラスバジム前後、D・Hイベントの邪魔にならないフラグ

暴走したメガ個体との1戦、端末停止、キーストーン受取。必須ワープを塞がず、敗北しても本編フラグを巻き戻さない。

## EVT-05 三島の試練

ひのしま、かみなりのしま、こおりのしまに各1NPC。三つ全てを必須にせず、一つ達成でZリング、残りはZクリスタル報酬。

## EVT-06 全国生態調査開始

**場所:** 殿堂入り後のハクジ研究所

```text
if not FLAG_HALL_OF_FAME -> end
setvar RESEARCH_RANK 0
setflag NATIONAL_RESEARCH_DEX
unlock SAFARI_RESEARCH_WING
unlock FOSSIL_LAB
unlock STARTER_RESEARCH
```

トーホク図鑑完成チェックの関数は変更しない。

## EVT-07 御三家研究

地方を選ぶ→その地方に対応した3件の調査→3個のタマゴを順に受取。最初の一匹を選んでも残りが消えない。

## EVT-08 巨人の間

既存のちえのどうくつB2Fから小部屋へワープ。レジロック・アイス・スチル、後にレジエレキ・ドラゴ、最後にレジギガス。各石室は個別フラグ。

## EVT-09 スフィア裂け目

同じ共通マップを背景・パレット・出現テーブルだけ切替えてUBとパラドックスに再利用。入場前に対象群を表示し、チケットを消費する。

## EVT-10 無限炉心レイド

D・H反応炉でムゲンダイナ。ダイマックス許可マスクをこの戦闘だけ有効化。初回捕獲後は素材レイドへ差替え。

## EVT-11 仮面祭

ハクジタウンに祭りNPC4人、森に固定戦4体。新規大型マップは不要。オーガポンを先に助けることで、三体の悪役化を簡潔に説明する。モモワロウは最後に解禁。

## EVT-12 捕獲救済管理人

研究所の管理人が、次の条件を満たした倒済み伝説を復活させる。

```text
for each legendary_event:
  if defeated && !captured && respawn_epoch < hall_of_fame_count:
      clear defeated
      set symbol_visible
      respawn_epoch = hall_of_fame_count
```

交換で図鑑だけ埋まっていても、イベント未捕獲なら戦える。捕獲済みなら再出現しない。

## イベント実装規則

- 既存必須イベントと同じフラグを再利用しない。
- 追加NPCはイベント数上限、OWパレット、movement scriptを監査。
- 追加ワープは帰還先を必ず設定し、あなぬけのヒモ／テレポートを試験。
- 固定戦直前に捕獲済み、手持ち、PC、袋、SaveBlockバージョンを確認。
- イベント文はベガの語彙・文字送り速度に合わせ、長い現代用語を説明口調にしすぎない。

## 意図的な境界

- PokeAPIの後発データ混入を防ぐため、フォームは `pokemon_id<=10277` に限定。10278以降のLegends Z-A系メガ等は含めない。
- 通常薬、一般きのみ、通常宝物、全TMは、CFRU実ビルドから正確な道具定数を抽出後にカテゴリ規則で生成する。PokeAPIの全2223道具を無差別に入れない。
- 同じ進化元・進化先に複数条件がある行は重複ではなく代替条件。`evolution_id`で一意管理する。

## 実ROMで未実施の検査

1. CFRU/DPEフックの期待バイトとベガ実バイトの一致。
2. ベガ内部の種族、技、道具、特性、トレーナー、マップ、フラグ、special番号の実値抽出。
3. SaveBlock、PC25箱、図鑑1025ビット、フォーム、DexNavのセクタ配置。
4. 32 MiBリンカ配置、ポインタ範囲、アラインメント、空き容量。
5. 新規ゲーム、全ストーリー、捕獲、進化、預入、育て屋、殿堂入り、セーブ／ロードの実行回帰。
6. 1戦1ギミック、メガ／Z／ダイマックス／テラ終了時のフォーム復帰。

実装者は `templates/hook_audit.csv` と `templates/build_manifest.json` を埋め、上記を全てPASSにしてから配布パッチを生成する。
